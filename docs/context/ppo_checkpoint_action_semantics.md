# PPO checkpoint action semantics and release plant limitation

The release PPO checkpoint (`ppo_expert_issue_791_reward_curriculum_eval_aligned_large_capacity_20260417`) and Guarded PPO primary checkpoint (`ppo_expert_br06_v3_15m_all_maps_randomized_20260304T075200`) declare `action_semantics: velocity_delta` in [the model registry](../../model/registry.yaml): their signed output is added to current physical `(v, omega)` before target clipping, projection, guard arbitration and the existing velocity-to-acceleration adapter. The training plant allowed 3.0 m/s and reverse motion and applied instantaneous, unscaled velocity deltas without a timestep multiplier; release evaluation retains the same plant as every other arm, with a 2.0 m/s cap, no reverse and ±1 m/s² / rad/s² acceleration limits. Correcting action interpretation therefore does **not** reproduce historical training transitions; this plant mismatch remains a method limitation and changed trajectories are not comparable with earlier absolute-action release rows except as diagnostic comparisons. BR-06 has training source `9fb131b6d7ff062887caab33ca8713ae05167ebe`; the canonical PPO training commit remains null, and its declared semantics follow PPOS's evidence for the era's single environment pipeline at launch-config commit `0202ccfab592090ec1cca12b266d3131ed484b37`, whose drive code is identical to BR-06's source. The effective adapter contract is `ppo-target-velocity.v2`; missing or contradictory declarations for these checkpoints fail closed. See issues [#9750](https://github.com/ll7/robot_sf_ll7/issues/9750) and [#9668](https://github.com/ll7/robot_sf_ll7/issues/9668).
