# 0.0.8 preparation: development-only planner-tuning protocol

This is a protocol release note for issue #9748, not a statement that 0.0.8 has been evaluated or
published. It records the [28 September 2026 author decision](https://github.com/ll7/robot_sf_ll7/issues/9748#issuecomment-5864715937).

Modified planners must use **pre-registered development-only scenario-parameter variants, using
disjoint seeds and identities not present in the release matrix.** The registered tuning seeds are
1001–1030. The four development identities use the existing doorway, group-crossing,
perpendicular-traffic and crowd-navigation maps with exactly the approved density/jitter changes.
There is no new SVG spawn/goal geometry, and none of these identities is a release row.

Definitions, per-variant hashes and existing map identities are recorded before tuning in
`configs/benchmarks/planner_development_freeze_v1.json`. Materialized definitions require review
before use. Tuning configs and logs must pass `scripts/validation/check_planner_tuning_split.py`;
the check fails on references to release seeds 111–140 and on changed frozen inputs. Full policy,
values, provenance, supported formats and commands are in the
[development split README](../../configs/benchmarks/planner_tuning/README.md).

PR #9747's earlier runs on seeds 111–140 are pre-protocol diagnostics only. Their numbers are not
reported benchmark evidence and do not become development evidence by relabelling. Preserve the
historical artifacts and the 0.0.7 release unchanged.

After development-only tuning, record the final modified-planner config/closure hashes and tuning
log before the held-out release evaluation. No further change is made to that planner for the same
release after evaluation. This applies equally to hybrid v4, socnav_sampling v2 and social force
v2. The definition-freeze PR itself performs no tuning or release evaluation, chooses no final
planner settings, changes no release roster, and supports no performance or generalization claim.
